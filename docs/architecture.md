# Architecture

## Routes and rendering

- Four static entry points: `/` and `/en/` render the landing page; `/portfolio/` and `/en/portfolio/` render the project catalog. Each has its own title, canonical URL and bilingual alternatives. Native Next links handle navigation between pages.
- `features/site/SiteShell.tsx` composes the persistent header, context and Framer Motion providers in the root layout. One shared translucent closing panel groups capabilities, contact and footer on every page; its inner sections stay transparent so there are no solid rectangles cutting through the metal background. The contact uses two compact columns on desktop and stacks on mobile. `features/landing/Landing.tsx` and `features/portfolio/Portfolio.tsx` only compose their own page content. Translation, theme, navigation and product presentation have separate domain boundaries.
- The brand links to the hero in the current language. Same-page section controls explicitly request smooth scrolling without creating hash URLs. Global CSS does not enable smooth scrolling: Next 16 otherwise applies it to route restoration, which can leave the hero offscreen. Page changes remain instant. `features/navigation/` centralizes route generation and section scrolling; existing `#top`, `#work` and contact bookmarks are migrated to clean paths.
- `features/language/useLocale.ts` synchronizes URL, document language and metadata. Native History API language changes preserve the mounted page, selected project, catalog filters and shader. Browser back/forward and direct reloads retain the correct language and page.
- The app has one locally served variable font (Stack Sans Headline, also used by Clyra). Next downloads it at build time; visitors do not contact a font provider. All content is exported to HTML before hydration.
- `scripts/finalize-static.mjs` fixes both English documents' static language attributes and generates hashes for inline hydration scripts. The generated CSP permits those exact scripts, not arbitrary inline JavaScript.
- There is no contact form, analytics, tracking, employment-history section or invented client/revenue metric.

## Visuals and behavior

- `lib/site.ts` owns the display name **Damian Perez**, with initial capitals, no accents and no punctuation suffix. The hero, shared brand links, credits, project label, 404 page and metadata use that same value; the share image follows the same spelling. `HeroBadges` presents three localized specialties (full-stack, product design and applied AI) in compact monochrome pills with icons and a hover reflection. Typography remains unchanged.
- `HeroWork` balances the asymmetrical introduction with two small, layered glass previews of AgentOS and OmniCube and a bilingual note about his end-to-end approach. It reuses the catalog and `DeviceMockup` projection without duplicating product content. The preview is one keyboard-accessible link to the current language's portfolio; hover gently separates the cards and reduced motion disables that movement. On mobile the composition follows the introduction, within the document flow. The chrome scene stays visible around and through the previews.
- `Landing` selects those two projects on the server and passes them to the client hero. Shared media helpers live in `data/projectMedia.ts`, independently of the full catalog, so landing visitors do not need the other 21 project descriptions in their JavaScript.
- `features/background/` owns Shader Metal by Jay Sharma / 23rd.dev (MIT). Its original ribbon geometry, normals and studio reflections are adapted to a neutral chrome palette with distinct light/dark lighting. One persistent canvas and worker serve both the hero and project catalog. Pointer movement steers the light and gently bends the ribbons; reduced motion holds a still frame. OffscreenCanvas moves compilation and drawing off the UI thread, with native WebGL fallback. The hook owns all listeners and resources. Parallel shader compilation, 30 fps, a 2-million-pixel budget (at most 2x density), hidden-tab/reduced-motion/data-saving suspension and disposal bound its work. There is no shader CDN or added runtime dependency.
- The neutral shader fixes the existing five-ribbon material at compile time, omits its unused iridescence calculations and obtains the spine tangent analytically instead of evaluating the same curve three times. Canvas resolution, frame rate, lighting, pointer interaction and composition remain the same. The main-thread compatibility renderer is imported only when the worker cannot be used, rather than duplicating the shader in the initial client bundle.
- Project surfaces use translucent theme colors and real `backdrop-filter: blur(16px)` so the continuous metal ribbons soften behind the mockups. The stylesheet compiler supplies vendor prefixes; declaring the prefixed property after the standard property caused it to drop the standard declaration in this Next version, so explicit duplicate prefixes are avoided.
- The transparent fixed header gains a fading backdrop blur after scrolling. It offers separate home and portfolio links, theme/language controls and contact. Mobile navigation closes on selection or Escape and restores keyboard focus.
- `features/theme/` owns the stored monochrome preference and Clyra's circular View Transition, originating at the clicked control. A CSP-hashed bootstrap applies the saved palette before paint. Unsupported browsers, reduced motion and hidden tabs commit immediately. Canvas paint acknowledgements ensure the new theme is present before its transition snapshot. A temporary bitmap freezes an offscreen canvas for the old capture: Chrome otherwise keeps that texture live, letting the new palette leak outside the reveal circle. The bitmap and temporary canvas are released after capture; pending snapshots time out or cancel with their worker. Pending transitions are cancellable on route changes; denied storage still permits a session theme change.
- `features/language/` contains Clyra's text roll, wipe and 3D turn effects. The hero name makes a small refractive shift when language changes; existing controls and artwork remain mounted. Reduced motion commits readable content immediately.
- `FeaturedProjects` presents six products through a keyboard-accessible carousel without autoplay. The catalog starts with eight cards in four desktop columns and two mobile columns; filters expose matching products and expansion exposes all 23.
- `DeviceMockup` uses Clyra's published frames and screen geometry. `utils/screenProjection.ts` maps real captures to photographed displays; `ResizeObserver` maintains proportions. Concept art and product stages remain explicitly identified. Decorative mockups do not duplicate accessible card names.
- `CaptureImage` selects real light/dark exports from the shared theme preference for every hero preview, carousel, catalog display and dialog capture. `useAlternateCapture` warms the opposite palette at low priority only when a screen enters the viewport. Visible images participate in the existing theme transition's decode barrier, so the circular reveal captures the new screenshots together with the new chrome lighting. Theme changes preserve the selected gallery slot; single-palette captures keep their original appearance in both themes. Each capture retains Clyra's own focal position.
- A lazy-loaded native dialog presents mockups, full screenshots (up to six views per product), project details, arrow navigation, Escape, focus containment/restoration and scroll locking.
- Contact copying distinguishes success from rejection and retains the mailto fallback.

## Content and assets

The 23 projects, EN/ES descriptions and permanently redacted captures originate from `clyra-dev/clyra`, revision `1d44066ceb3d96c6abf98bdd8f5798caa58addd5`. The redesign also reuses its published device mockups, projection geometry and first product views, one font family, circular theme reveal and language text motion. The previous Clyra radial shader, magnetic/orbiting name and liquid-glass buttons were removed. Shader Metal comes from `radiumcoders/23rd.dev`, revision `e59481fefedf2101a133d3049e907fa02580a3db`, `registry/shader-metal/shader-metal-vanilla.ts`. Only public portfolio assets and presentation code were copied. Prototype and in-development labels remain explicit; concept artwork is labeled in the project dialog.

`features/portfolio/data/projects.json` is the bilingual catalog and source provenance. `data/projects.ts` provides typed contracts; `data/projectMedia.ts` resolves local asset paths. The source capture paths in JSON are provenance; the site serves its own optimized WebP files.

`node scripts/import-project-captures.mjs /path/to/clyra` reproducibly imports the published capture manifest from the pinned Clyra revision above. It rejects a different or locally modified source collection, preserves the 98 logical gallery views (52 paired and 46 supplied in one palette), and exports only the real variants listed in that manifest. Palette-specific filenames and versioned URLs keep the two themes separate in browser/CDN caches. Concept art remains theme-independent. The script removes obsolete theme-blind exports only after the complete import succeeds.

After importing captures, run `node scripts/build-responsive-images.mjs`. It adds 320px capture variants and 320/640px device frames from the existing public assets, preserving their crop and alpha, and records native capture widths in `data/captureWidths.json`. Native `<picture>` selection uses the real projected screen size and display density: small previews download small assets, while large screens and full galleries retain their resolution. The opposite theme preloads the same responsive size only after the visible capture loads; data-saving connections skip that speculative request. The featured cover preload uses the same responsive candidates to avoid downloading an unused large copy.

`public/projects/` includes 320px compact captures, 640px previews, 960px covers and gallery images up to 1600px. The browser selects an appropriate candidate for each displayed screen; larger gallery assets become available when a detail opens. Lazy loading reduces transfers. Responsive device frames live in `public/mockups/`; their original coordinate system is preserved when resizing the frame assets. Gallery images retain their full proportions. The catalog lists each public capture as provenance. Versioned capture URLs prevent browsers from reusing the previous redesign’s thumbnails after deployment. Original personal portrait was optimized to 132px. Obsolete fonts and 83 MB of older portfolio images were removed from the working tree; originals remain in Git history.

`scripts/build-background-worker.mjs` bundles the typed worker with esbuild before development and production builds. The generated `public/effects/metal-worker.js` is ignored in Git and served locally with revalidation; application code, shaders and the worker protocol remain in `features/background/`. No worker CDN or runtime dependency is needed.

## Hosting and security

`wrangler.jsonc` pins personal Cloudflare account `ad8dddf36a3fc53dca424e763e4a153e`.

- Production Worker: `damian-pebe-portfolio`, custom domain `damianperez.dev`.
- Staging Worker: `damian-pebe-portfolio-staging`, isolated workers.dev URL and no production domain routes.
- Output: `out/`, static assets only, native 404 page and trailing slash handling.
- `src/workers/canonicalRedirect.ts` with `wrangler.redirect.jsonc`: separate `damian-portfolio-redirect` Worker, 308 www-to-apex redirect preserving path and query. Workers Static Assets does not support hostname conditions in `_redirects`; canonical requests remain assets-only.
- `public/_headers`: TLS policy, frame denial, MIME-sniffing protection, bounded browser permissions and cache policy.
- Hashed framework assets are immutable for one year. Project images use versioned URLs and are immutable for one year; bump `assetVersion` when replacing them. Device frames use a one-day cache with stale-while-revalidate. HTML revalidates.
- No secrets, cookies, customer data, server processes or runtime dependencies are hosted.
- All four HTML routes send `Cache-Control: public, max-age=0, must-revalidate, no-transform`. This prevents Cloudflare's automatic analytics injection from altering the static document or conflicting with its hashed CSP. Other asset routes retain their compression and caching policies. See [Cloudflare Web Analytics automatic injection](https://developers.cloudflare.com/web-analytics/get-started/).
